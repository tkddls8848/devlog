# devlog — 개발 일지

GitHub 공개 저장소의 커밋을 날짜별 개발 일지로 정리합니다.

운영 사이트: <https://devlog.tkddls8848.workers.dev/devlog/>

수집·Workers AI 생성·D1 저장·서비스는 Cloudflare Worker `devlog`에서 실행됩니다.
Cron Trigger `10 0 * * *`가 매일 09:10 KST에 실행하며, 발행 결과를 로컬 Markdown이나
GitHub 커밋으로 저장하지 않습니다. 기존 61편과 커밋 정보는 D1으로 이관했습니다.

`devlog/` 폴더에는 이전 GitHub Pages 구현과 수집기 테스트가 남아 있지만 운영 데이터의
원본은 아닙니다. 운영 코드는 `news/worker/devlog.mjs`, 화면 라우팅은
`news/worker/index.mjs`, D1 스키마는 `news/migrations/0003_devlog.sql`에 있습니다.

## 기술 회고 생성과 화면

`shared/devlog-writing.mjs`에서 운영 Worker와 이전 로컬 수집기가 쓰는 작성 기준을
함께 관리합니다. 커밋 제목·본문에 더해 실행당 최신 날짜의 최대 12개 커밋에서
변경 파일 4개와 파일당 diff 1200자를 가져옵니다. AI 입력은 최대 40개 커밋,
직렬화된 근거 22,000자로 제한하며 발췌 범위를 함께 전달합니다. 상세 조회가
실패하면 메시지만 사용하고, 참고 커밋은 생략 없이 보존합니다.

글은 구현 근거, 설계상 의미·비용, 남은 질문과 다음 검증으로 이어지는 기술 회고를
지향합니다. 실제 경력이나 시행착오를 만들지 않으며, 코드 변경과 실행·배포 결과를
구분합니다. AI 응답이 불완전하거나 생성이 실패하면 기존 커밋 기록으로 발행합니다.

`shared/devlog.css`와 `shared/devlog.js`는 빌드 시 각 사이트의 assets로 복사됩니다.
운영 개발 기록 화면에는 최신 글 강조, 제목·요약 검색, 본문 목차, 코드 블록,
예상 읽기 시간, 펼쳐 보는 참고 커밋을 제공합니다. 검색은 현재 목록에 로드된 글을
대상으로 합니다. 운영 목록은 최대 100편입니다.

변경된 작성 기준은 이후 생성되는 글부터 적용됩니다. 이미 D1에 발행한 글은
자동으로 다시 쓰지 않습니다. 실제 모델의 문장 품질은 운영 AI로 별도 확인해야 합니다.
