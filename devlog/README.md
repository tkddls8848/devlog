# devlog — 작업 회고

그날의 커밋으로 AI가 작업 기록을 쓰고, 작성자가 편집기에서 다듬는 작업 회고입니다.

운영 사이트: <https://devlog.tkddls8848.workers.dev/devlog/>

수집·작성·D1 저장·서비스는 Cloudflare Worker `devlog`에서 실행됩니다.

## 저장소 공개 범위에 따른 작성 기준

비공개 저장소의 작업도 회고 주제로 다룰 수 있다. 비공개 작업은 개별 기술 문제,
일반화한 해결 방법, 작업 과정과 배움을 설명한다. 코드·diff와 프로젝트 전체 목적,
제품 구상, 핵심 시나리오, 사업 방향, 미공개 로드맵은 공개하지 않는다.
국소적인 기술 이유(중복 요청 방지 등)는 설명하되 제품의 전체 목표는 설명하거나 추론하지 않는다.
원문에 전체 목표가 명시되어 있어도 공개 글에는 옮기지 않는다.

프로젝트를 식별할 수 있는 저장소 이름·URL, 커밋 SHA·원문 메시지, 내부 파일 경로,
고유 기능명은 그대로 노출하지 않고 일반화한다. 제목·요약·본문·참고 링크와
이를 재사용하는 영상 대본에도 동일하게 적용한다.

예: '미공개 서비스의 전략과 핵심 기능을 구현했다' 대신
'중복 요청이 들어왔을 때 작업이 두 번 실행되지 않도록 처리 흐름을 정리했다'처럼 쓴다.
구체적인 변경과 검증 결과는 확인된 사실만 사용한다.

공개 이벤트와 함께 인증된 `/user/repos`에서 본인 소유 비공개 저장소를 수집한다.
비공개 저장소는 기본 브랜치의 최근 7일 커밋을 대상으로 한다.
`DEVLOG_PRIVATE_LOOKBACK_DAYS`로 1~90일 범위를 지정할 수 있다. 보관·비활성 저장소와
타인·조직 소유 저장소는 제외한다. 목록과 커밋은 각각 최대 10페이지까지 수집하며,
조회 실패나 페이지 한도 도달은 실행 상태를 `partial`로 기록한다.
기존 공개 이벤트도 저장소의 현재 공개 범위를 조회하고, 확인에 실패하면 수집을 보류한다.

비공개 원문 메시지와 코드는 AI 입력·참고 자료에 넣지 않는다. 커밋 제목에서
인증·권한·중복 요청·재시도·타임아웃·캐시·입력 검증·예외 처리·페이지 처리·테스트·로깅·배포·리팩터링
유형을 판별해 고정된 기술 요약만 만든다. 구체적인 구현 효과나 성공 결과를 추측하지 않는다.
알 수 없는 유형은 분류하지 못했다는 문장만 남긴다. 자동 요약은 보수적이므로 세부 판단과 배움은
작성자가 공개 가능한 범위로 추가할 수 있다. 직접 입력하는 본문의 의미까지 자동 검열하지는 않는다.

실제 저장소명과 SHA는 내부 D1의 중복 수집 방지·관리용으로만 보관한다.
공개 본문과 참고 자료에는 안정적인 별칭과 대체 식별자를 쓰고, 공개 커밋 링크 목록에서는 제외한다.
영상 설명에도 비공개 커밋 링크를 만들지 않는다. 재작성에도 같은 비식별 기준을 적용한다.
이미 발행한 과거 글이나 이전 로컬 내보내기 파일을 자동으로 소급 수정하지는 않는다.

운영 반영은 `0005_devlog_privacy.sql` 마이그레이션 적용 후 Worker를 배포한다.
`GITHUB_TOKEN`에는 대상 비공개 저장소의 Metadata·Contents 읽기 권한이 필요하다.
토큰이 허용하지 않는 저장소는 GitHub 목록에서 보이지 않을 수 있으므로 토큰의 저장소 선택도 확인한다.

## 자동 작성과 발행

Cron Trigger `10 0 * * *`가 매일 09:10 KST에 공개 커밋을 모아 날짜별 작업 기록을
**써서 바로 발행**합니다. 글은 "AI 자동 작성"으로 표시되고, 작성자가 편집기에서 고쳐
저장하면 "작업 회고"로 바뀝니다. Worker 변수 `DEVLOG_AUTO_PUBLISH=false`이면 쓴 글을
초안으로만 두고 발행은 작성자가 합니다.

- 형식은 2026-09-24 기록을 따릅니다. 저장소 수와 커밋 수로 시작하는 첫 문단, 커밋이
  많은 저장소부터 `## 저장소` 소제목, 그 아래 줄글로 무엇을 왜 했는지·부딪힌 문제의
  원인과 해결·측정 결과·남은 일. 커밋 메시지에 없는 내용은 쓰지 않고, 검증이 없으면
  없다고 씁니다.
- 저장소마다 따로 불러 병렬로 씁니다(`news/worker/devlog-writer.mjs`, 모델
  `@cf/openai/gpt-oss-120b`, `DEVLOG_WRITER_MODEL`로 교체). 하루치를 한 번에 쓰면 바쁜
  날에는 출력 상한에 잘리거나 업스트림 시간 제한(약 4분)에 걸렸습니다. 첫 문단은 개수로
  만들고, 제목·요약은 본문을 보고 마지막에 씁니다. 잘린 응답은 다시 시도하고, 그래도
  안 되면 소제목만 둔 초안으로 남깁니다.
- 같은 날짜에 작성자가 이미 쓰기 시작한 초안이 있으면 AI가 덮어쓰지 않고, 참고 자료와
  빠진 저장소 소제목만 덧붙입니다.
- 편집기의 `AI로 본문 다시 쓰기`는 참고 자료의 커밋 근거로 제목·요약·본문을 새로 씁니다.
  저장하기 전까지는 반영되지 않습니다.
- 커밋이 많은 날은 1~3분 걸립니다.

`devlog/` 폴더에는 이전 GitHub Pages 구현과 수집기 테스트가 남아 있지만 운영 데이터의
원본은 아닙니다. 운영 코드는 `news/worker/devlog.mjs`, 화면 라우팅은
`news/worker/index.mjs`, D1 스키마는 `news/migrations/0003_devlog.sql`,
`0004_devlog_journal.sql`에 있습니다.

## 하루 회고 쓰기 (웹 편집기)

<https://devlog.tkddls8848.workers.dev/devlog/admin/>에서 로그인해 씁니다.

- **글 관리**: 쓸 차례인 초안과 발행한 글을 나눠 보여 줍니다. 날짜를 골라 커밋이 없는
  날의 글도 새로 만들 수 있습니다.
- **편집기**: 제목·요약·본문을 쓰고, 오른쪽 참고 자료(질문, AI 참고 문구, 커밋 근거)를
  보며 작성합니다. 미리보기 탭, 글자 수, Ctrl+S 저장, 저장하지 않고 떠날 때 경고,
  브라우저에 남는 임시 백업을 제공합니다.
- **참고 자료**: 편집기에는 질문, AI 참고 문구, 커밋 메시지만 보입니다. 변경 파일 목록과
  줄 수, 코드 diff 발췌, 커밋 트레일러(`Co-Authored-By` 등)는 숨깁니다. D1에는 그대로
  남아 있어 영상 워크플로와 CLI(`npm run journal -- pull`)는 계속 씁니다.
- **맞춤법 검사**: 본문 탭 옆 `맞춤법 검사`를 누르면 Workers AI(`@cf/openai/gpt-oss-120b`,
  `DEVLOG_SPELLCHECK_MODEL`로 교체 가능)가 제목·요약·본문에서 맞춤법·띄어쓰기·표기 오류를
  찾아 제안합니다. 제안마다 `적용`/`무시`를 고르며, 원문에 그대로 있는 구절만 제안으로 남기고
  코드는 건드리지 않습니다. AI 제안이라 틀린 것도 있으니 직접 확인하고, 적용한 뒤 저장해야
  반영됩니다. 1,800자 글 기준 20~30초 걸립니다.
- **저장소별 소제목**: 초안은 그날 커밋이 있던 저장소마다 `## 저장소` 소제목을 미리
  넣은 채로 만들어집니다(Cron 초안, `새 글 쓰기` 모두). 각 소제목 아래에 그 프로젝트
  이야기를 씁니다. 나중에 같은 날 커밋이 더 모이면 빠진 저장소 소제목만 뒤에 붙고, 쓴
  내용은 건드리지 않습니다. 편집기의 `빠진 소제목 넣기`로 직접 넣을 수도 있습니다.
  발행할 때 비어 있는 소제목이 있으면 발행하지 않습니다(쓰거나 지우면 됩니다). 이
  소제목으로 영상 워크플로가 본문을 저장소 세션에 정확히 나눕니다.
- **새 글 쓰기**: 고른 날짜에 아직 발행하지 않은 초안이 있으면 새로 만들지 않고 그
  초안을 엽니다.
- **상태**: 초안은 `임시 저장`/`발행하기`, 발행한 글은 `저장하고 반영`/`비공개로 돌리기`.
  발행은 제목과 본문이 있어야 하며, 거절돼도 쓴 내용은 그대로 남습니다.
- 로그인한 상태로 공개 화면을 보면 목록에 `글 관리 · 새 글 쓰기`, 글마다 `이 글 수정`
  링크가 보입니다. 이 화면은 캐시하지 않습니다(`private, no-store`).

로그인 비밀번호는 Worker secret `DEVLOG_ADMIN_PASSWORD`입니다. 길이 제한은 없지만 비어 있거나 등록하지
않으면 아무도 로그인할 수 없습니다.

```bash
cd news
npx wrangler secret put DEVLOG_ADMIN_PASSWORD
```

로그인하면 30일짜리 서명 쿠키(`HttpOnly; Secure; SameSite=Strict; Path=/devlog`)를
받습니다. 비밀번호를 바꾸면 모든 기기의 로그인이 끊깁니다. 쓰기 요청은 같은 사이트에서
온 것만 받고(`Origin` 확인), 틀린 비밀번호에는 응답을 늦춥니다. 코드는
`news/worker/devlog-auth.mjs`, `devlog-admin.mjs`, 편집기 스크립트는
`shared/devlog-editor.js`에 있습니다.

## 로컬 파일로 쓰기 (CLI)

편집기 대신 로컬 에디터를 쓰고 싶다면 `news` 폴더에서 wrangler 로그인으로 운영 D1에
접근하는 CLI도 있습니다.

```bash
cd news
npm run journal -- list                   # 아직 쓰지 않은 초안
npm run journal -- pull 2026-09-24        # devlog/journal/<slug>.md 로 받기
# 파일을 열어 title, summary, 본문을 쓴다
npm run journal -- publish ../devlog/journal/2026-09-24-devlog.md
```

받은 파일은 세 부분으로 나뉩니다.

1. 머리말: `title`, `summary`를 채웁니다. 제목의 기본값은 `YYYY-MM-DD 작업 회고`입니다.
2. 본문: 안내 주석 아래부터 참고 자료 표시 줄 위까지가 발행되는 글입니다.
   `##`/`###` 소제목, 목록, `**강조**`, 인라인 코드, 코드 블록을 쓸 수 있습니다.
   HTML 주석은 발행 때 빠집니다.
3. 참고 자료: `<!-- devlog:reference ... -->` 줄 아래는 발행되지 않습니다.
   - 쓰기 전에 떠올려 볼 질문: 커밋에 남지 않는 계기, 막힌 지점, 버린 대안, 실제 확인 여부
   - AI 참고 문구: 제목·요약 후보, 하루의 흐름, 작업 흐름별 '무엇을 했나'·'왜 했나'·
     고쳐 쓸 참고 문장·직접 채울 부분, 다음에 이어서 할 일. 코드 이야기는 넣지 않습니다.
   - 커밋 근거: 저장소별 커밋의 전체 메시지, 변경 파일과 줄 수, 주요 파일의 diff 발췌

`publish`는 제목·요약이 비었거나 본문이 200자 미만이면 발행하지 않습니다.
`--dry-run`으로 실행할 SQL만 볼 수 있고, `--local`이면 로컬 D1을 씁니다.
이미 발행한 글도 `pull <slug>`로 받아 고친 뒤 다시 `publish`할 수 있습니다. 처음
발행 시각은 유지하고 수정 시각만 바뀝니다. 작성 중인 파일을 덮어쓰지 않도록
`pull`은 같은 파일이 있으면 멈추며, `--force`를 붙여야 덮어씁니다.

`devlog/journal/`의 파일은 작업 사본입니다. 운영 원본은 D1이며, 파일을 커밋해 두면
쓴 글의 이력이 git에도 남습니다.

## 초안과 참고 자료 생성

`shared/devlog-writing.mjs`가 참고 자료의 형식과 AI 지시문을 관리합니다. 커밋
제목·본문에 더해 실행당 최신 날짜의 최대 12개 커밋에서 변경 파일 목록(최대 30개)과
줄 수, 변경량이 큰 소스 파일 4개의 diff 1200자를 가져옵니다. README·테스트·잠금
파일은 diff 발췌에서 뒤로 밀립니다. 이 파일·diff 정보는 영상 워크플로용으로 저장만 하고,
AI에는 커밋 메시지만 보냅니다(최대 40개 커밋, 22,000자). 작성자가 코드가 아니라 무엇을
왜 했는지를 쓰기 때문입니다. 상세 조회나 AI가 실패해도 커밋 근거만으로 초안을 남깁니다.

같은 날짜에 아직 발행하지 않은 초안이 있으면, 다음 실행에서 모인 커밋은 새 초안을
만들지 않고 그 초안의 참고 자료 뒤에 덧붙습니다. 이미 발행한 날짜에 새 커밋이 오면
`YYYY-MM-DD-devlog-2` 같은 새 초안이 생깁니다.

AI 참고 문구는 완성된 글이 아니라 고쳐 쓸 재료입니다. 동기, 시행착오, 검증 결과처럼
커밋만으로 알 수 없는 내용은 만들지 않고 '직접 채울 부분'으로 남기도록 지시합니다.
실제 모델이 이 지시를 얼마나 지키는지는 운영 초안으로 확인해야 합니다.

## 화면

공개 화면은 발행한 글(`status = 'published'`)만 보여 줍니다. 직접 쓴 글은 '작업 회고',
전환 전에 AI가 자동 발행했던 글은 '이전 AI 자동 기록'으로 표시합니다. 이전 글은
그대로 공개되며, `pull <slug>`로 받아 다시 써서 발행하면 '작업 회고'로 바뀝니다.

`shared/devlog.css`와 `shared/devlog.js`는 빌드 시 각 사이트의 assets로 복사됩니다.
최신 글 강조, 제목·요약 검색, 본문 목차, 코드 블록, 예상 읽기 시간, 펼쳐 보는 참고
커밋을 제공합니다. 운영 목록은 최대 100편입니다.
